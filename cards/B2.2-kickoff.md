## Summary
- What is wanted: `local:start` and read-only `status`. LOCAL is the only
  admitted execution flow: every card and AI step runs on this host, while
  builds and long test lanes MAY run model-free on GitHub Actions. The old
  `remote:start` remains registered only to refuse with its retirement
  wording before configuration reads or state changes. Status reports local
  execution and in-flight runs without dispatching anything.
- Why it matters: the old two-mode design forced a false choice between
  local AI and remote compute. The current boundary keeps agents steerable
  and resumable locally while still allowing GitHub to absorb model-free
  build work.

## Context
- Kickoff sentences (pinned): "Ask only blocking questions." "Batch blocking
  questions together." "State non-blocking assumptions and continue."
  "Keep working until blocked, completed, or an operator decision is required."
- Start accepts a goal, a readable ledger path, or ledger plus supporting
  goal. Any readable ledger shape is coordination source material; an
  unreadable path errors with the path named, never falls back to a default.
- `local:start` records `Execution: local`. In that mode local subagent desks
  run every AI step, and `gh-build.py run`, `gh-full-lanes.py run`,
  `gh-snapshot.py publish` and `gh-wait.py` remain available for MODEL-FREE
  work under their caps. No tool may start a cloud AI task.
- `remote:start` and cloud-step claim/start/check/park/resume/release answer
  `REFUSED retired: running AI on GitHub is not feasible; run the step
  locally; GitHub is for model-free builds and test lanes only`. The refusal
  happens before config reads, GitHub calls and state changes. Any other
  `WORKFLOW_MODE` value also fails closed.
- A bare legacy `start` records nothing and points to `local:start`; a legacy
  `Execution: remote` in old state is labelled RETIRED, never offered as a
  current choice. Status reads B0.3's run state and never acts on it.
- Guidance: "The Card Is the Contract" (the cloud lane lost; local AI and
  model-free GitHub compute).

## DESIGN SELF-CHECK
1. Claims and pins: each start/status/mode claim maps to guarantee (a)-(e);
   no claim says local mode disables model-free GitHub compute.
2. Constants: kickoff sentences, execution values and retirement text have
   one source; tests read them rather than paraphrase.
3. Shared state and test order: each start uses a fresh state fixture;
   refusal tests assert state before and after are identical.
4. Inherited environment: every mode test sets `WORKFLOW_MODE` explicitly
   and removes it for the invalid/unset controls; no config leaks between
   fixtures.
5. Mutant kills: M1-M5 name their tests; M5 also has a valid local control
   proving the build tools still run.
6. Composition: B0.3 owns run state, B1.2 injection, B2.1 roles; B4.1/B4.2
   consume this one local-only mode contract, not a second mode table.
