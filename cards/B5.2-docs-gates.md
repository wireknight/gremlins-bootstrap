## Summary
- What is wanted: the docs and environment health gates wired into the
  battery and pre-push fast tier: the anchor linter (B1.0's `lint-anchors.py`,
  invoked — one implementation, never a second), the cross-reference graph
  and consistency sweep (B3.3's `synchronize.py`, invoked), the generated-views
  and template `render --check` check (reporting drifted, missing, or extra
  generated files and steering extra-file drift to deleting the file), and
  `doctor.py` (verifying that hooks, pinned tools, and the doctrine digest
  are actually installed and fresh on the machine doing the work, refusing
  to point a main checkout's shared hooks dir at a linked worktree).
- Why it matters: these gates are what make the repository's words
  trustworthy enough to be an agent's reading material — and `doctor.py`
  answers the question the gates themselves cannot: are the gates actually
  on?

## Context
- One source per law: the anchor linter and the consistency sweep exist as
  stage 1 (B1.0) and stage 3 (B3.3) artifacts; this card only registers them
  as battery suites with fail-closed wiring. A second implementation of
  either is a mutant-class defect, not a convenience.
- Unreadable input is INCOMPLETE: an in-scope doc that cannot be read makes
  the affected gate print `UNREADABLE <tool> <path>` and exit 2. It never
  disappears from the census and produces a clean result.
- The views and render check: every generated view (indexes, counts,
  rendered workflow/step templates) is checked byte-for-byte against its
  generator; a drifted or missing file fails, and an extra file in a
  rendered directory fails with a steering message to delete the extra file
  (`render --write` never deletes files).
- Doctor (`doctor.py`): classifies each hook (`pre-commit`, `commit-msg`,
  `pre-push`) as `ok`, `missing`, `dangling`, `foreign`, `wrong-target`, or
  `not-executable`; `--fix-hooks` moves any replaced entry aside to a
  printed `.backup.<n>` path (never deletes) and refuses (exit 2) when
  `--root` is a linked worktree whose common dir holds the hooks dir being
  judged or written.
- Guidance: "The Anti-Rot Machine" (generated views vs hand-written
  contracts; a truncated index is a lying index); "Dura Lex, Sed Lex"
  (cite-by-reference as the enforced rule).

## Failing test
- Test file / class: `tests/test_docs_gates.py::TestWiringAndDoctor`
- Guarantee it asserts: (a) the docs-gate suite invokes B1.0's linter and
  B3.3's sweep by their entry points (pinned by import/entry assertion,
  proving no second implementation ships); (b) a fixture tree with one
  dangling anchor fails the suite; (c) a fixture committed index differing
  from its regeneration, or an extra file in a rendered template directory,
  fails the suite and the extra-file error steers to deleting the file; (d)
  `doctor.py` flags a `not-executable` or `dangling` hook as `FAIL`, backs
  up replaced hooks under `--fix-hooks`, and refuses (exit 2) when `--root`
  is a linked worktree sharing the target's hooks dir; (e) the suite is
  registered in the battery's suite list (absent registration = incomplete
  run per B5.1); (f) an unreadable in-scope doc is INCOMPLETE with its path
  named, never silently clean.
- Command: `python3 -m pytest tests/test_docs_gates.py -q`
- exact failure on the base commit (when the red test is run before
  `suites/docs-gates.py` and `scripts/doctor.py` exist): exit code 1,
  `FileNotFoundError` / `ModuleNotFoundError` (`suites/docs-gates.py` not
  found).

## Mutants
- M1 (fork of the law): the suite ships its own inline anchor check instead
  of invoking B1.0's. `TestWiringAndDoctor::test_one_implementation`
  must turn red.
- M2 (dangling passes): a fixture dangling anchor yields green.
  `test_dangling_fails` must turn red.
- M3 (stale view or extra rendered file passes): a committed index differing
  from regeneration or an extra rendered file yields green.
  `test_views_and_render_check` must turn red.
- M4 (doctor blind to non-executable hook or linked worktree): `doctor.py`
  reports `OK` on a non-executable hook symlink or allows a linked-worktree
  `--root` to repoint shared hooks. `test_doctor_classifications_and_worktree_guard`
  must turn red.
- M5 (unreadable becomes clean): a doc gate drops an unreadable in-scope
  file from its census and exits 0. `test_unreadable_is_incomplete` must
  turn red.

## Doctrine
- Principles engaged: one source per law; neither side is the source of
  truth, the pair is; generated views are rebuilt, never trusted; verify the
  gates themselves are installed and executable.
- Why this validation is sufficient: every way the docs and environment
  gates can rot (reimplementation, tolerated danglings, stale views or extra
  files, silent broken hooks) is a mutant.

## DESIGN SELF-CHECK
1. Claims and pins: one-source, view, doctor, registration and unreadable
   claims map to (a)-(f); no claim lets unreadable input count as checked.
2. Constants: hook classes, render verdicts and battery registration names
   come from the invoked tools; tests do not duplicate their logic.
3. Shared state and test order: fixture trees and hook homes are isolated;
   doctor backup paths are checked after an explicit replacement only.
4. Inherited environment: all gate/doctor fixtures remove inherited git
   repository variables and explicitly construct linked-worktree state.
5. Mutant kills: M1-M5 name their tests; readable valid docs and executable
   hooks provide green controls.
6. Composition: B1.0 and B3.3 own the checks; B5.1 owns completeness; this
   terminal card only wires them and owns doctor.
