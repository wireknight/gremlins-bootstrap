## Summary
- What is wanted: the two deterministic gates and the commit-gates installer
  (`install-commit-gates.sh`). Pre-commit: the fast lints on the staged
  paths (the write gate's lint, staged `@Anchor --index` check, syntax
  checks), no model in the loop, seconds not minutes. Pre-push: the fast
  tier (including template `render --check`) and the suite sweep on the
  pushed commit, with honest skips (turned into failures when
  `REQUIRE_GATES=1`). Both scrub inherited git environment variables
  (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`,
  `GIT_PREFIX`) so an outer hook or linked worktree never redirects a check
  onto the wrong checkout, and both fail closed: a red holds the operation,
  and nothing ever rewrites the remote.
- Why it matters: this is the rung of the ladder that makes the correct way
  the only way out of the building. The push gate stays local and unbypassed;
  a mechanical integration desk may invoke it, but no role may skip it.

## Context
- Honest skips: a suite that cannot run in this environment (missing
  toolchain) prints its skip reason and does not fail the gate by default,
  but fails closed when `REQUIRE_GATES=1`; a suite that RUNS and fails is a
  red, never a skip.
- A red at the pushed commit holds the push even when a later local commit is
  green; the pushed bytes are the judged bytes.
- Watchdog and timeouts: the pre-push sweep can take minutes; its budgets
  live in one configuration, it must never be killed silently into a pass,
  and watchdog expiry kills the expired call's owned process tree and emits
  a steering line naming the exhausted budget and its remedy.
- Linked-worktree guard: `install-commit-gates.sh` installs or `--verify`s
  `pre-commit` and `commit-msg` only (never `pre-push`), and refuses (exit 2)
  when run from a linked worktree whose `hooks` dir is shared through
  `git-common-dir` with the main checkout.
- Guidance: "The Enforcement Pipeline" (the ladder, hook prices, the rung as
  return channel); "A Million Tests Is Still a Survey" (the battery's
  honesty).

## Failing test
- Test file / class: `tests/test_hooks.py::TestFailClosed`
- Guarantee it asserts: (a) a staged violating file makes pre-commit exit
  non-zero with the violation named, even when `GIT_DIR` / `GIT_WORK_TREE`
  point at another repository; (b) a failing suite makes pre-push exit
  non-zero; (c) a missing-toolchain suite prints `SKIP <suite>: <reason>` by
  default and fails under `REQUIRE_GATES=1`; (d) `install-commit-gates.sh`
  installs and `--verify`s `pre-commit` and `commit-msg` only, and refuses
  (exit 2) inside a linked worktree; (e) pre-push never issues a
  remote-write command (pinned by a dry-run fake remote that fails the test
  on any push-like call).
- Command: `python3 -m pytest tests/test_hooks.py -q`
- exact failure on the base commit (when the red test is run before
  `scripts/git-pre-commit-hook.sh`, `scripts/git-pre-push-hook.sh`, and
  `scripts/install-commit-gates.sh` exist): exit code 1, `FileNotFoundError`
  / `AssertionError` (hook scripts not found).

## Mutants
- M1 (fail-open): pre-push exits 0 when a suite fails.
  `TestFailClosed::test_red_suite_holds_push` must turn red.
- M2 (silent skip): a failing suite is skipped with no reason printed, or
  `REQUIRE_GATES=1` still allows a skip. `test_skip_is_loud_and_honest` must
  turn red.
- M3 (inherited `GIT_DIR` leak): pre-commit honors an inherited `GIT_DIR`
  pointing at a clean decoy repo and passes a violating staged file.
  `test_git_env_scrubbed` must turn red.
- M4 (linked-worktree hook hijack): `install-commit-gates.sh` links the
  main checkout's shared hooks dir to a linked worktree's scripts.
  `test_linked_worktree_refused` must turn red.

## Doctrine
- Principles engaged: deterministic gates, no model in the loop; fail closed;
  honest skips never silently pass; the judged bytes are the pushed bytes;
  never corrupt a shared hooks directory from a linked worktree.
- Why this validation is sufficient: every way a gate can lie (fail-open,
  quiet skip, inherited `GIT_DIR`, linked-worktree hijack) is a mutant that
  must turn red.

## DESIGN SELF-CHECK
1. Claims and pins: fail-closed, skip, environment, worktree and watchdog
   claims map to (a)-(e); no claim lets a mechanical desk bypass pre-push.
2. Constants: hook names, environment-variable list and budget configuration
   have one source; tests import them rather than re-type.
3. Shared state and test order: hook repositories and remotes are isolated;
   watchdog tests measure TERM before KILL and never use global cleanup.
4. Inherited environment: each fixture deliberately poisons git variables
   for the scrub case and removes them for the clean control.
5. Mutant kills: M1-M4 name their tests; the valid remote and clean staged
   fixture prove the gates do not reject everything.
6. Composition: B1.1/B1.3 supply doctrine checks; B4.2 owns admission and
   process supervision; B5.1 owns the battery invoked by this one hook.
