## Summary
- What is wanted: the LOCAL compute substrate (`host-admission.py`,
  `build-lock.py`, `gh-local-lane.py`) that replaces the retired remote
  environment and cloud step controller. Every AI launch, resume and wave
  passes host/provider admission. Every registered local build runs through
  a host-wide build lock and leaves an admission id. A mechanical local lane
  writes a model-free manifest that B4.1/B5.1 can reconcile. Projects also
  declare host shapes so topology-sensitive greens cannot overclaim.
- Why it matters: local-first does not mean the host is an unmeasured
  fallback. Capacity, process ownership, exact bytes, fresh reports and
  hardware coverage all need receipts, especially while GitHub carries the
  model-free lanes that fit its runners.

## Context
- Admission (pinned): before every launch, resume and wave, a model-free
  probe reports memory pressure, swap, free disk on the launch volumes,
  load against operator-reserved cores, live runs across EVERY session on
  the host, and the provider cap. Unreadable means HOLD. A held call is
  durably QUEUED with its exact arguments and rechecked on completion;
  nothing is dropped. Concurrency is sized to free slots, not the config's
  ambition. The operator's admission/cap files are never edited by agents.
- Build lock (pinned): every local build of a registered project runs as
  `build-lock.py run --project <name> --tree <worktree> --args <lane args>`.
  A run that could not take the lock did not happen and its output is not
  evidence. Every admission mints `adm=` and every request `request=`; an
  identical live tree+command is DUPLICATE. Cancel removes a queued request
  only, never an admitted build. DONE comments cite admission ids, and the
  verifier compares them with the lock log.
- Liveness and cleanup (pinned): unknown or unreadable process-start state
  assumes ALIVE, never dead; only verified-gone or a verified different
  start can recycle identity. Owned subprocess cleanup escalates TERM before
  KILL after a grace, with owned-output draining so a chatty child cannot
  deadlock the probe. There is no global process-name cleanup.
- Local lane manifest (pinned): `gh-local-lane.py` requires a clean checkout
  of HEAD and admission, executes configured `{args}` plus fresh args,
  collects fresh reports, and atomically writes `agent-local-reports/1`
  with `format`, `sha`, `tree`, `label`, `command`, `exit_code`,
  `started_utc`, `ended_utc`, `reports`. A local red is evidence; dirty tree,
  held admission, stale reports and invalid config refuse without a success
  manifest. A dead build's no-reports manifest is evidence of death, never
  green.
- Host shapes (pinned): a project declares CPU-count/NUMA/other topology
  shapes beside its lanes. A card that reads topology names the covering
  shape and whether it ran on a real host or a test-SIMULATED topology the
  test controls. A lane that cannot reach a declared shape is NOT covering
  it; byte-exact timing/allocation verdicts remain on target hardware, with
  GitHub an early signal only. Lanes are not multiplied by default.
- No cloud AI environment, agent profile, cloud step controller or READ
  receipt is built. Retired members refuse through B2.2.
- Guidance: "The Card Is the Contract" (local execution is evidence only
  with admission; hardware truth is scoped; the cloud lane lost).

  turn red.

  KILL arrives without a preceding TERM. `test_owned_cleanup_is_bounded`

## Doctrine
- Principles engaged: unadmitted work is not evidence; unknown is not dead;
  owned processes only; local red is evidence; unreachable hardware is a
  coverage gap, never a pass.
- Why this validation is sufficient: admission bypass, unsafe liveness,
  receipt laundering, stale manifests, topology overclaim and unsafe cleanup
  each have a killing mutant.

## DESIGN SELF-CHECK
1. Claims and pins: every admission/lock/lane/shape claim maps to (a)-(e);
   no claim treats local execution as inherently trustworthy.
2. Constants: manifest keys, lock states, exit codes and shape declarations
   live in the shared modules/config; tests import them.
3. Shared state and test order: hermetic lock homes and process trees are
   isolated; TERM/KILL and admission/log ordering are measured explicitly.
4. Inherited environment: every subprocess runs with inherited git
   repository variables removed and only the fixture's admission settings.
5. Mutant kills: M1-M6 name their tests; M2 and M6 include live-process and
   successful-cleanup controls proving the simulations took effect.
6. Composition: B0.3 owns recovery, B1.4 hooks, B4.1 remote evidence; B5.1
   consumes this card's manifests and lock log without reimplementing them.
