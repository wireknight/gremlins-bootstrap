## Summary
- What is wanted: `run-battery.py`, sharded `gh-full-lanes.py`,
  `gh-reconcile.py`, and `push-ready.py`. The battery runs every configured
  suite with caps and honest skips. Full lanes runs every configured shard
  model-free on GitHub, never passing a missing shard. Reconciliation uses
  B4.1's classified runs and B4.2's same-sha local manifests, records every
  cleared remote red against an investigation card, and leaves the local
  pre-push gate unchanged. Push readiness is then read from ONE manifest by
  a model-free checker before any collection push.
- Why it matters: the last gate can lie by dropping a suite, absorbing a
  red, comparing different bytes, or letting the coordinator remember which
  verdicts exist. Complete evidence and a mechanical readiness answer keep
  the gate honest.

## Context
- Battery summary: every suite/shard appears with outcome and wall time;
  `PASS`, `FAIL`, `SKIP`-with-reason and `SHARD-INCOMPLETE` are explicit.
  Timeout is red. Missing-toolchain skip fails under `REQUIRE_GATES=1`.
  A suite or shard absent from the summary is incomplete, never green.
- Reconciliation (pinned): same sha only. `SHARED-RED` and
  `REPRODUCED-LOCALLY` block; `NOT-YET-RUN-LOCALLY` is owed and blocks;
  `LOCAL-RED` blocks; `RUN-INCOMPLETE` blocks and trusts no line. A
  `NOT-REPRODUCED` red or locally covered `SHARD-INCOMPLETE` unblocks only
  with `--investigation <sig>=<card>`; otherwise `investigation=OWED` and
  exit 1. An exclusive-lane result is owed until its local lane covers it.
- Recorded, never absorbed: a remote red or death cleared by B4.1's ONE
  local rerun is recorded as a new investigation card or a comment on the
  open card with the same failure signature, including run id. The card
  under review may proceed, the question does not close, and repeated
  signatures accumulate on that one card. `flaky`/`transient` without a card
  is refused. `RECONCILE CLEAR` is not push permission.
- Push manifest and rules (pinned): coordinator state, not tracked, one
  file per collection with name/tip, each card's commits and `verification`,
  `final`, `pre_review` verdicts as `{verdict, evidence-link}`, and standing
  reds as `{test, state, reason-when-deleted}`. Desks never write verdicts;
  the coordinator records them as they land.
- Tracked `.cards/push-rules.json` names only `verification-required`,
  `final-required`, `pre-review-required`, `no-standing-reds`, each with its
  ruling date and words. Unknown names refuse. Passing verdict words live in
  `push-ready.py` alone. The checker prints one gap per line and `READY
  <collection> <tip>` only with none (exit 0 READY, 1 gaps, 2 malformed).
  It runs before readiness/progress answers and every collection push;
  non-READY means no push. The pre-push gate still runs independently.
- Guidance: "A Million Tests Is Still a Survey" (battery honesty); "The Card
  Is the Contract" (recorded reds and model-free push readiness).

## Mutants
- M1 (fail-open): a failing/capped suite or missing shard counts as passed.
  `TestLanesReconcileAndPushReady::test_failure_timeout_and_missing_are_red`
  must turn red.
- M2 (red absorbed): a locally cleared remote red disappears with no
  investigation card, or a second local rerun hides it.
  `test_cleared_remote_red_is_recorded_once` must turn red.
- M3 (wrong bytes): reconciliation accepts a local result from another sha.
  `test_reconcile_requires_same_sha` must turn red.
- M4 (unknown rule passes): an unknown push-rule name or passing word is
  silently accepted. `test_unknown_rule_refused` must turn red.
- M5 (memory becomes READY): the coordinator pushes with a missing verdict
  or standing red, or treats RECONCILE CLEAR as push permission.
  `test_non_ready_never_pushes` must turn red.

## Doctrine
- Principles engaged: missing evidence never passes; a cleared red is
  recorded, not forgotten; verdict authority stays with verifiers/reviewers
  while the checker transcribes; local pre-push remains independent.
- Why this validation is sufficient: fail-open, absorbed reds, wrong-byte
  comparisons, unknown-rule acceptance and memory-based readiness each have
  a killing mutant.

## DESIGN SELF-CHECK
1. Claims and pins: lane, reconcile and readiness claims map to (a)-(e); no
   claim makes RECONCILE CLEAR or the coordinator's memory a push approval.
2. Constants: reconciliation classes, rule names, passing words and manifest
   keys have one implementation; tests import them.
3. Shared state and test order: each run/reconcile/manifest fixture is
   isolated; investigation and verdict order is asserted explicitly.
4. Inherited environment: all fixture CLIs run with inherited git repository
   variables removed and explicit same-sha inputs.

   control proving reconciliation is not simply always blocked.
6. Composition: B4.1 supplies classified runs and one-rerun queue; B4.2
   supplies local manifests; B1.4 supplies the independent push gate; B5.2
   registers, never reimplements, these checks.
