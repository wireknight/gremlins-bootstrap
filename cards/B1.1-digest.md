## Summary
- What is wanted: one script that renders the doctrine (numbered rules across
  one or two layers: the runtime's own layer, and optionally a project layer)
  into a single generated digest for injection and inspection.
- Why it matters: every later surface (injection, gates, the docs tests)
  consumes this one view. A lying or silently truncated digest poisons all of
  them; a loud one is safe to build on.

## Context
- The doctrine lives as markdown files with numbered headings (HR-N style).
  Two layers: the runtime layer from its docs tree, and, when configured, a
  project layer from the adopting project's own docs directory.
- The digest is a generated view, never hand-written; a truncated index is a
  lying index.
- Smallness is by reference, guarded by a loud fail-closed budget: the
  digest carries headings and numbers and resolves rule bodies by pointer
  (it never copies rule bodies), and if a layer still exceeds its byte
  budget the generator exits 3 naming the layer, the byte count, and the
  budget (never silent truncation).
- Guidance (the why-layer): the article "Dura Lex, Sed Lex", the sections on
  injection and enforcement; the article "The Card Is the Contract" on
  generated views. The repo doc outranks the articles where they diverge.

## Failing test
- Test file / class: `tests/test_digest.py::TestUnionAndBudgets`
- Guarantee it asserts: (a) on a two-layer fixture, stdout is the union of
  both layers, each layer's entries under its heading; (b) a fixture whose
  project layer exceeds its budget makes the run exit 3 with a message naming
  the layer, the byte count, and the budget; (c) two rules with the same
  number in one layer appear as a CONFLICT entry flagging both, never merged;
  (d) `--stdout --surface session` prints only the digest, nothing else.
- Command: `python3 -m pytest tests/test_digest.py -q`
- exact failure on the base commit (when the red test is run before
  `scripts/generate-doctrine-digest.py` exists): exit code 1,
  `FileNotFoundError` / `AssertionError`
  (`scripts/generate-doctrine-digest.py` not found).

## Mutants
- M1 (silent truncation): edit the script so an over-budget layer is emitted
  truncated, exit 0. `TestUnionAndBudgets::test_over_budget_exits_three` must
  turn red with "exit code 0 != 3".
- M2 (merge on conflict): edit so duplicate-numbered rules keep the last one.

## Doctrine
- Principles engaged: fail loud over silent degradation; smallness by
  reference with a loud budget, never silent truncation; a generated view
  cannot fork its source.
- Why this validation is sufficient: every guarantee is pinned by a test that
  fails at the base, and every bypass of it is a mutant that must turn red.

## DESIGN SELF-CHECK
1. Claims and pins: union, budget, conflict and stdout claims map to (a)-(d);
   no claim permits an over-budget digest to pass by truncation.
2. Constants: layer names, headings and budget values come from fixture
   configuration; tests never re-type a production default as their oracle.
3. Shared state and test order: doctrine fixtures are independent; union
   output order is the only ordered behavior and is asserted explicitly.
4. Inherited environment: generator fixtures run with explicit doctrine
   roots and no inherited project or git variables.
5. Mutant kills: M1-M3 name their tests; the under-budget control proves
   valid input still renders.
6. Composition: B1.0 supplies anchors; B1.2 consumes this one digest; B1.4
   runs its suite without a second digest generator.
