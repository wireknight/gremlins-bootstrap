## Summary
- What is wanted: seven LOCAL step contracts — design, card-check, red
  (`s1`), red-confirmed (`vr`), fix (`s2`), verified (`vf`), final — each a
  markdown file with front matter (`step`, `role`, `version`, `may_add`), a
  normal-order section, a STOP rule, and its evidence schema. Reports carry
  semantic outcomes, not the retired cloud runner's answer vocabulary.
  Every AI step runs on this host; no step launches a cloud agent.
- Why it matters: the step files are the card machine's law. They must make
  the normal proof order and its two declared exceptions explicit without
  pretending the retired remote step protocol is still the runtime.

## Context
- Step-to-role and `may_add` bindings (pinned): design → `designer`
  (`card`); card-check → `verifier` (`evidence`); red (`s1`) →
  `implementer` (`tests`); red-confirmed (`vr`) → `verifier` (`evidence`);
  fix (`s2`) → `implementer` (`code`); verified (`vf`) → `verifier`
  (`evidence`); final → `designer` (`evidence`). `advisor` is optional and
  never a verdict authority; `judge` is invoked only on B3.2's escalation
  triggers, never as a default step.
- Normal order (pinned): red test alone and STOP; independent exact-red
  confirmation on committed bytes; fix plus one-at-a-time mutants; verifier
  re-runs checks and mutants on committed bytes; final reads evidence.
  The two exceptions are TEST-ONLY STRENGTHENING and small-fix, with the
  eligibility and proof shapes in PROTOCOL.md. No desk may invent another.
- Evidence at `vr` and `vf` (pinned):
  `.cards/evidence/<card>/<step>/provenance.json` with
  `{"version": 1, "sha": <sha>, "runs": [{"command", "tree", "exit_code", "started_utc", "ended_utc", "mutant"}]}`.
  At `vf`, each mutant patch is written from the card's words, its
  `patch_sha256` recorded, and its tree id computed in a temporary git
  index (`git read-tree`, `git apply --cached`, `git write-tree`).
- Final evidence (pinned): for every changed production function, the
  covering tests and whether each RAN or was SKIPPED in fresh reports. All
  skipped or uncovered HOLDS the card unless the card states why no executed
  test can exist and names the lane that will execute it.
- Issue-ledger audit tokens (bootstrap only, not cloud answers): a NORMAL
  card's R, V and M phases end `RED-CONFIRMED-N`, `VERIFIED-N`, `ACCEPTED-N`
  respectively so `merge_card.py` can transcribe them. Negative outcomes
  void automerge. Other steps use semantic outcomes in their evidence.
- Forbidden in every step file: `READ STEP`, `READ COMMENT`, cloud task
  claim/start/check/park/resume/release operations, and `remote:start` as a
  live route. Historical references must say `RETIRED` or `ARCHIVED`.
- Guidance: "The Card Is the Contract" (the normal order, declared
  exceptions, local landing); PROTOCOL.md (the seed phases these automate).

## DESIGN SELF-CHECK
1. Claims and pins: every local-step claim maps to guarantee (a)-(f); no
   claim asserts a live read receipt or cloud step.
2. Constants: step names, role names, paths and audit tokens are the pinned
   surfaces; tests read them from the contracts rather than invent variants.
3. Shared state and test order: fixtures are independent; the only order is
   the normal card order explicitly under test.
4. Inherited environment: subprocess fixtures remove git repository
   variables except when a test explicitly pins that boundary.
5. Mutant kills: M1-M5 each name the exact test that must fail; no control
   is allowed to turn the archived-protocol absence check green by deletion.
6. Composition: no predecessor. B0.2 and B0.4 consume these files; overlap
   with their later stages is by dependency, never concurrent editing.
