## Summary
- What is wanted: the synchronize specialist: a sweep that keeps the written
  contracts and the code agreeing, in both directions, plus the findings
  ledger it records into — stable ids, append-only, every entry traceable to
  the run that found it.
- Why it matters: metadata rots silently, and agents read everything and
  hallucinate the gaps. The sweep turns rot from a mood into a graph
  problem: dangling edges and stale multiplicities, checkable exhaustively.

## Context
- Direction one (code keeps docs true): every symbol a doc names exists in
  the code; every doc reference carries an `@Anchor` (a stable identifier,
  not a line position) and the anchor resolves with the quote it claims.
- Direction two (docs keep code true): pinned doc-assertions — statements a
  doc makes that a test derives from the code; a green build never coexists
  with a disagreement.
- Generated views (indexes, counts) are built from hand-written contracts,
  never edited by hand; a truncated index is a lying index, and an extra
  unlisted file in a rendered set steers the operator to deleting the file.
- Findings ledger format: stable id, the finding, the evidence, the status
  (`OPEN` / `FIXED` / `ADJUDICATED-KEPT`), the run that found it; stored
  reproductions are never auto-executed.
- Guidance: "The Anti-Rot Machine" (the rot graph; the confabulation guard;
  evidence-based fixes — model-suggested reproductions never auto-run).

## Failing test
- Test file / class: `tests/test_synchronize.py::TestRotGraph`
- Guarantee it asserts: (a) a fixture doc naming a deleted symbol is
  reported as a dangling edge with the doc path and the symbol; (b) a
  fixture doc claiming "three implementations" against a tree with two is
  reported as a stale multiplicity; (c) a generated index omitting one
  hand-written entry is reported as lying; (d) ledger entries keep their ids
  across re-runs (id stability pinned); (e) the sweep never edits a file it
  sweeps (tree hash unchanged).
- Command: `python3 -m pytest tests/test_synchronize.py -q`
- exact failure on the base commit (when the red test is run before
  `scripts/synchronize.py` exists): exit code 1, `FileNotFoundError` /
  `ModuleNotFoundError` (`scripts/synchronize.py` not found).

## Mutants
- M1 (silent dangling): dangling edges are dropped from the report.
  `TestRotGraph::test_dangling_edge_reported` must turn red.
- M2 (count laundering): stale multiplicities are re-derived from the code
  and the doc is auto-rewritten. `test_sweep_never_edits` must turn red.
- M3 (lying index passes): a truncated generated index is accepted.
  `test_generated_view_completeness` must turn red.
- M4 (id churn): re-running the sweep assigns new ids to known findings.
  `test_ledger_ids_stable` must turn red.

## Doctrine
- Principles engaged: rot is a graph problem, checkable exhaustively;
  neither side is the source of truth, the pair is; evidence-based fixes
  only.
- Why this validation is sufficient: every way a sweep can lie or damage
  (hidden rot, auto-rewriting, lying indexes, id churn) is a mutant.

## DESIGN SELF-CHECK
1. Claims and pins: both directions, generated views and ledger claims map
   to (a)-(e); no claim lets the sweep heal the disagreement it measures.
2. Constants: anchor form, ledger fields and status values come from B1.0
   and the shared ledger module; tests import them.
3. Shared state and test order: swept trees are independent; ledger ids are
   compared across two explicit runs of the same fixture.
4. Inherited environment: sweep fixtures run with clean environments and
   inherited git repository variables removed.
5. Mutant kills: M1-M4 name their tests; a clean doc/code pair is the green
   control proving the sweep does not invent rot.
6. Composition: B1.0 supplies anchors, B3.1 the record contract, B5.2 wires
   this one sweep into the battery without reimplementation.
