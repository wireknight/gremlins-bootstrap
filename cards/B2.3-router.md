## Summary
- What is wanted: the issue router. It reads `Pickup`, `Work class`,
  `Execution tier`, and `Verifier`, routes once, and stays sticky. Missing,
  empty or contradictory fields error with the fix named. Work-class and
  executor collisions are refused. QA has its own explicit ref and never
  passes through this generic router; judge and advisor are invoked
  explicitly, not manufactured as default issue lanes.
- Why it matters: a router that guesses makes independence decorative. The
  new QA and small-fix lanes need the same refusal discipline as the normal
  implementation, verification and mechanical lanes.

## Context
- Fields (pinned): `Pickup`, `Work class`, `Execution tier`, `Verifier`.
  Each value is captured on its OWN line; horizontal whitespace never
  crosses a newline, so an empty value fails rather than swallowing the next
  field's keyword. The first word of Work class declares the class;
  remaining text is description.
- Work classes (pinned): `implementation`, `reasoning`, `review`,
  `verification`, `mechanical`, `small-fix`.
- Routes and refusals (pinned): implementation → implementer only (the
  second implementer is selected by explicit ref); reasoning and `/prospect`
  → designer only; final review → designer, cheap first-pass review →
  verifier; verification, `/verify` and `/synchronize` → verifier;
  mechanical → mechanical. Implementation on designer/verifier/mechanical,
  reasoning on verifier/mechanical, review on implementer/mechanical,
  non-reasoning non-review work on designer, and non-mechanical work on
  mechanical are refused with the correct route named.
- QA (`/qa`, `/qa --bug-scan`) → the QA role at max by explicit ref, never
  `issue-auto`. Judge and advisor are also explicit dispatches: judge only
  on B3.2's triggers; advisor only for a second opinion and never a verdict.
- Small-fix → the default Sonnet implementer only, never the second
  implementer ref. It batches cosmetic findings by
  area and requires linters, ONE quick independent check per item from a
  different family, a finding→edit→linter record, the coordinator's batch
  diff review, and the pre-push gate. It skips the red/mutant/full-battery
  cycle only inside the allowed classes: typos, wording, broken links and
  anchors, stale numbers, comments, formatting, and code proven
  unreferenced. Anything bigger leaves the lane and becomes a normal card.
- Sticky: one route per task; a second request returns the same route
  without re-reading or re-deciding.
- Guidance: "The Card Is the Contract" (dispatch discipline, separate QA,
  the small-fix exception); "Untrusted Labor in a Trusted Envelope"
  (routing fields are contract).
