## Summary
- What is wanted: persistent run state and model-free recovery
  (`scripts/run-state.py`, `scripts/inherited-runs.py`, `scripts/if-cut.py`).
  Every desk's rolling report ends with a completion sentinel only at
  close. A scanner classifies each run from its OWN status and receipt,
  restores any applied mutant before resume/relaunch, and produces one
  session-wide TODO set that cannot launch a second writer.
- Why it matters: a dead driver's summary is not evidence about its
  children. Local autonomy survives interruption only when completion,
  restoration and relaunch are measured from durable bytes.

## Context
- Run root (pinned): a durable path derived from the main checkout's git
  common directory, ignored by git, inherited by every desk. Starting inside
  a repository is required; an unset, relative, wrong-root or unignored root
  is a loud setup error. `git clean -x` on that root is forbidden.
- Completion (pinned): `complete` without the final sentinel is PARTIAL;
  RUNNING and DONE under any driver are excluded from the session-wide TODO;
  NEVER-LAUNCHED and TODO are computed once for the whole session. A stale
  pid is reconciled before any action. UNKNOWN never means DONE.
- Resume/relaunch (pinned): a retryable rate-limit or connection cut resumes
  the SAME child within configured bounds. A request-size cut relaunches
  FRESH from the rolling report because resume would resend the same body.
  A stopped run is never resumed. A stopped workflow driver is relaunched
  with the same script, cwd and args; a successor uses `reuseFrom` only in
  the same run root and must prove re-attachment from the journal.
- IF-CUT (pinned): before any mutant or instrument is applied, the desk
  writes `IF CUT WHILE APPLIED:` to `agent-if-cut` in the worktree's OWN git
  directory and saves originals in `agent-if-cut.d/`. The note clears only
  after a hash-proven restore. A pending note blocks resume/relaunch until
  restored; WIP is preserved, never stashed or checked out destructively.
- No READ receipt: this card proves completion and restoration, not that a
  model read or understood a source.
- Guidance: "The Card Is the Contract" (receipted failures, fresh versus
  resumed handoffs); "Never Ask a Model If It's Right" (measure the run's
  own evidence, never the driver's narration).

## Doctrine
- Principles engaged: the run's own bytes are the evidence; completion is
  not narration; restore before relaunch; never launch a second writer;
  unknown never becomes success.
- Why this validation is sufficient: every dangerous shortcut (driver
  narration, duplicate work, oversized resume, abandoned mutant, unknown
  promoted to success) has a killing mutant.

## DESIGN SELF-CHECK
1. Claims and pins: each recovery guarantee maps to (a)-(f); no claim says
   recovery proves reading or saves a run whose bytes were never persisted.
2. Constants: status names, sentinel position, IF-CUT paths and action names
   come from the recovery modules; tests import them.
3. Shared state and test order: hermetic run roots are independent; ordered
   resume/relaunch sequences are explicit and no fixture reuses a live key.
4. Inherited environment: every fixture removes inherited git repository
   variables before calling recovery; the explicit git-dir boundary itself
   is exercised with linked worktrees.
5. Mutant kills: M1-M5 name their tests, and each fixture proves the fault
   was actually installed before asserting the guard's result.
6. Composition: B0.2 supplies reports; B2.2 and B4.2 consume recovery state;
   no other card may write these recovery modules in parallel.
