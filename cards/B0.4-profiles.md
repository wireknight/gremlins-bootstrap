## Summary
- What is wanted: seven thin LOCAL role profiles (`designer`,
  `implementer`, `verifier`, `qa`, `advisor`, `judge`, `mechanical`). Each
  binds to the step file, maintains B0.2's rolling report, writes its
  completion sentinel only at close, and STOPs when it cannot meet the
  standard. One additional sentence names that role's duty and permission
  boundary. No profile contains a READ-receipt or cloud-task contract.
- Why it matters: the profile is thin because law lives in the step file.
  Role separation is real only when each profile also refuses the powers
  that would let it grade its own homework.

## Context
- Binding sentence (pinned, identical in all seven): "Read the local step
  file your task names first: it binds over everything here."
- Report sentence (pinned): "Maintain the rolling report and write the
  completion sentinel last, only when the work and its evidence are done."
- STOP sentence (pinned): "A step you cannot meet to its standard is a STOP."
- Duty sentences (pinned by role): `designer` reasons, writes words and owns
  final review, never implementation; `implementer` makes every repository
  change from a normal card or declared small-fix batch; `verifier` measures
  on committed bytes and
  never implements; `qa` scans and reports, never gives the acceptance
  verdict; `advisor` gives second opinions, never verdicts; `judge` is
  read-only and enters only on B3.2's escalation triggers; `mechanical`
  runs chores and may only make a clean merge, commit generator output, or
  push through the unbypassed local gate, never a hand-written edit.
- Profiles carry no card text, code block, cloud task, READ line, or extra
  instructions beyond these four sentences and the role name.
- Guidance: "The Card Is the Contract" (role separation; QA distinct from
  verification; mechanical landing).

## Failing test
- Test file / class: `tests/test_profiles.py::TestThinLocalProfiles`
- Guarantee it asserts: (a) exactly seven profiles exist, one per role; (b)
  each contains the binding, report and STOP sentences plus its own duty
  sentence verbatim; (c) each is under 140 words with no code block or card
  body; (d) no profile contains a READ receipt or cloud operation; (e)
  advisor has no verdict authority, QA cannot accept, judge is escalation
  only, and mechanical cannot make a hand-written edit.
- Command: `python3 -m pytest tests/test_profiles.py -q`
- exact failure on the base commit (before `profiles/*.md` exist): exit 1,
  `AssertionError` / `FileNotFoundError: profiles`.

## Mutants
- M1 (archived report): a profile replaces the rolling-report sentence with
  `READ STEP`. `TestThinLocalProfiles::test_no_archived_receipt` must turn red.
- M2 (verdict leak): advisor gains acceptance authority or QA gains it.
  `test_advisor_and_qa_cannot_accept` must turn red.
- M3 (mechanical edits): mechanical gains permission to resolve a conflict
  by editing a file. `test_mechanical_writes_are_bounded` must turn red.
- M4 (routine judge): judge becomes a default final-review role.
  `test_judge_is_escalation_only` must turn red.
- M5 (fat profile): a profile exceeds the word ceiling with filler.
  `test_thin_means_thin` must turn red.
